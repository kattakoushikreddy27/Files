What is Angular?

Simple Definition

Angular is a JavaScript framework for building dynamic, interactive web applications. It's maintained by Google and provides a complete solution to build modern web apps with a structured, scalable approach.

Angular vs Regular JavaScript

❌ Without Framework (Vanilla JS)

HTML: Static structure

CSS: Styling only

JS: Manual DOM manipulation

❌ Hard to manage
❌ Code becomes messy
❌ Difficult to scale
❌ Prone to bugs

✅ With Angular

Components: Reusable UI pieces

Services: Shared business logic

Templates: HTML with powers

✅ Organized
✅ Reusable code
✅ Easy to maintain
✅ Scalable

Real-World Analogy

Think of Angular like LEGO blocks:

  • Each Block = Component (button, form, card) - Reusable pieces
  • Instructions = Template (HTML) - How it looks
  • Connection = Services - How blocks talk to each other
  • Storage = State - Information blocks hold

You can build complex applications by combining simple, reusable components!

Why Use Angular?

Top 7 Reasons to Choose Angular

1️⃣ Component-Based

Break UI into small pieces: Each component is independent and reusable. A button component can be used 100 times without duplicating code.

Makes code organized and maintainable

2️⃣ Two-Way Binding

Data auto-syncs: When user types in input, data automatically updates in code. When code changes data, input automatically updates.

Less code to write, fewer bugs

3️⃣ Dependency Injection

Share code easily: Services automatically provided to components. No need to pass data through 10 component levels.

Clean architecture, less coupling

4️⃣ Built-in Tools

Everything included: Routing, HTTP client, forms, testing tools. No need to install 10 different libraries.

One framework, complete solution

5️⃣ TypeScript Safety

Catch errors early: Typos and type mismatches caught before running code. IDE highlights mistakes immediately.

Safer code, better IDE support

6️⃣ Scalability

Handles large apps: Netflix, Google, Forbes use Angular. Can scale from small apps to massive enterprise applications.

Built for production

7️⃣ Performance & SEO

Fast and searchable: Optimized for speed. Works well with search engines. Angular Universal for server-side rendering.

Users find your site, pages load quickly

When to Use Angular

✅ Best Choice When:

  • Building large-scale enterprise applications
  • Need everything built-in (routing, forms, HTTP client)
  • Team prefers TypeScript and strong typing
  • Application has complex requirements
  • Need powerful dependency injection
  • Long-term project with scalability needs

❌ Maybe Not Best When:

  • Building simple static website
  • Team just wants to learn JavaScript quickly
  • Small project that doesn't need scalability
  • Need to learn in just a few days
  • Only building UI components, not a full app

Core Concepts Explained

1️⃣ Components

What: A Component is a reusable piece of UI (visual + logic combined)

Has 3 parts:

  • Template (HTML): How it looks
  • Class (TypeScript): Logic and behavior
  • Styles (CSS): Appearance
// User card component shows user info
@Component({
  selector: 'app-user-card',
  template: '<h1>{{userName}}</h1>',
  styles: ['h1 { color: blue; }']
})
export class UserCardComponent {
  userName = 'John'; // Data
}

user-card.component.spec.ts - Unit tests

2️⃣ Templates

What: HTML with Angular superpowers (dynamic content)

Syntax What It Does Example
{{ data }} Interpolation - Show data <h1>{{ userName }}</h1>
[property] Property binding - Set element properties <img [src]="imageUrl">
(event) Event binding - Listen to events <button (click)="deleteUser()">
[(ngModel)] Two-way binding - Sync both ways <input [(ngModel)]="userName">
*ngIf Conditional - Show/hide <div *ngIf="isLoggedIn">
*ngFor Loop - Repeat for each item <div *ngFor="let item of items">

Real-Life Template Example

<div class="user-form">
  <!-- Two-way binding -->
  <input [(ngModel)]="email" placeholder="Email">

  <!-- Conditional show/hide -->
  <p *ngIf="!isEmailValid" class="error">Invalid email</p>

  <!-- Event binding -->
  <button (click)="submitForm()">Submit</button>

  <!-- Loop through items -->
  <ul>
    <li *ngFor="let user of users">
      {{ user.name }} - {{ user.email }}
    </li>
  </ul>
</div>

3️⃣ Services

What: Shared code/data that multiple components can use

Why: Instead of copying code, put it in a Service and reuse it everywhere

// This Service fetches users from database
@Injectable()
export class UserService {
  constructor(private http: HttpClient) {}

  getUsers() {
    return this.http.get('/api/users'); // Get from backend
  }

  deleteUser(id: number) {
    return this.http.delete(`/api/users/${id}`);
  }
}

// Any component can use it
@Component({...})
export class ListComponent {
  constructor(private userService: UserService) {} // Inject service
  
  users = this.userService.getUsers(); // Use it
}

Two-Way Binding [( )] Both ways <input [(ngModel)]="name">

6️⃣ Dependency Injection

What: Automatic way to share code/services across components

❌ WITHOUT DI (Bad)

class UserList {
  userService = 
    new UserService();
  // Creates new copy
  // every time (wasteful)
}

✅ WITH DI (Good)

class UserList { constructor( private userService: UserService ) {} // Gets same shared copy }

Best Practices for Organization

  • ✅ Group by feature: Keep related components, services together
  • ✅ One component per file: Each file = one component
  • ✅ Shared folder: Put common components in shared folder
  • ✅ Name files clearly: user.service.ts, user-list.component.ts
  • ✅ Keep it flat: Don't create too many nested folders
  • ❌ Don't mix concerns: Don't put services in components folder
  • ❌ Don't create folders for single files: Overkill for small files

Data Flow Architecture

Unidirectional Data Flow: Parent passes data to children, children emit events to parent

Parent Component
↓ @Input
├─ Child Component 1
├─ Child Component 2
├─ Child Component 3

Child → Parent Communication:
Child emits event → Parent listens → Parent updates data → All children get new data

Best Practice: Use Services for unrelated components

Component Lifecycle

Hook When Called Use For Example
ngOnInit() After component created Fetch data, initialize Load user data from API
ngOnDestroy() Before component destroyed Cleanup, unsubscribe Cancel timers, free resources
ngOnChanges() When @Input changes React to input changes Update UI when data changes
ngAfterViewInit() After view rendered Access DOM elements Focus on input element

Change Detection

What: Angular's mechanism to detect when data changes and update the UI

Default Strategy: Angular checks everything for changes

OnPush Strategy: Only check when @Input changes or event fires (faster)

Most of the time, default is fine. Use OnPush for performance optimization.

Service Code Example - Database Communication

// user.service.ts - Handles all database communication @Injectable() export class UserService { private apiUrl = 'http://localhost:3000/api/users'; constructor(private http: HttpClient) {} // GET: Fetch all users from database getUsers(): Observable<User[]> { return this.http.get<User[]>(this.apiUrl); } // GET: Fetch one user by ID getUser(id: number): Observable<User> { return this.http.get<User>(`${this.apiUrl}/${id}`); } // POST: Create new user in database createUser(user: User): Observable<User> { return this.http.post<User>(this.apiUrl, user); } // PUT: Update existing user in database updateUser(id: number, user: User): Observable<User> { return this.http.put<User>(`${this.apiUrl}/${id}`, user); } // DELETE: Remove user from database deleteUser(id: number): Observable<void> { return this.http.delete<void>(`${this.apiUrl}/${id}`); } }

Component Using Service Example

// users-list.component.ts - Displays data from database @Component({ selector: 'app-users', template: ` <h1>Users List</h1> <div *ngFor="let user of users$ | async"> <h3>{{user.name}}</h3> <p>Email: {{user.email}}</p> <button (click)="removeUser(user.id)">Delete</button> </div> ` }) export class UsersComponent implements OnInit { users$: Observable<User[]>; // $ means Observable constructor(private userService: UserService) {} ngOnInit() { // Fetch users from database via service this.users$ = this.userService.getUsers(); } removeUser(id: number) { this.userService.deleteUser(id).subscribe(() => { // Refresh list after deletion this.users$ = this.userService.getUsers(); }); } }

HTTP Methods Comparison

Method Purpose Database Operation Example URL
GET Fetch data (READ) SELECT * FROM users GET /api/users
POST Create new data (CREATE) INSERT INTO users VALUES(...) POST /api/users
PUT Update existing data (UPDATE) UPDATE users SET ... WHERE id=5 PUT /api/users/5
DELETE Remove data (DELETE) DELETE FROM users WHERE id=5 DELETE /api/users/5

Async Pipe Usage

What: The | async pipe automatically unsubscribes from Observable (prevents memory leaks)

❌ Without Async Pipe (Memory Leak)

users: User[]; ngOnInit() { this.userService.getUsers() .subscribe(data => { this.users = data; }); // Subscription never ends! }

✅ With Async Pipe (Safe)

users$: Observable<User[]>; ngOnInit() { this.users$ = this.userService.getUsers(); } // In template: <div *ngFor="let user of users$ | async">

Error Handling

getUsers(): Observable<User[]> { return this.http.get<User[]>(this.apiUrl).pipe( catchError(error => { console.error('Error fetching users:', error); return throwError(() => new Error('Failed to load users')); }) ); }

Users List Component

@Component({ selector: 'app-users-list', template: ` <h1>Users</h1> <div *ngIf="loading" class="loading">Loading...</div> <div *ngIf="error" class="error">{{ error }}</div> <button (click)="goToCreateUser()">Add New User</button> <table> <thead> <tr> <th>Name</th> <th>Email</th> <th>Actions</th> </tr> </thead> <tbody> <tr *ngFor="let user of users"> <td>{{ user.name }}</td> <td>{{ user.email }}</td> <td> <button (click)="editUser(user.id)">Edit</button> <button (click)="deleteUser(user.id)">Delete</button> </td> </tr> </tbody> </table> ` }) export class UsersListComponent implements OnInit { users: User[] = []; loading = false; error = ''; constructor( private userService: UserService, private router: Router ) {} ngOnInit() { this.loadUsers(); } loadUsers() { this.loading = true; this.userService.getUsers().subscribe({ next: (data) => { this.users = data; this.loading = false; }, error: (err) => { this.error = 'Failed to load users'; this.loading = false; } }); } editUser(id: number) { this.router.navigate(['/users', id, 'edit']); } deleteUser(id: number) { if (confirm('Delete this user?')) { this.userService.deleteUser(id).subscribe({ next: () => this.loadUsers(), error: () => this.error = 'Failed to delete user' }); } } goToCreateUser() { this.router.navigate(['/users/new']); } }
