📁 Angular Folder Structure - SIMPLE GUIDE

Understand WHERE everything goes and WHY - No confusing technical terms!

🤔 What is Folder Structure?

Simple Idea:

A folder structure is like organizing your home:

  • Kitchen = where you cook
  • Bedroom = where you sleep
  • Living Room = where you sit

In Angular:

  • components/ = where you keep UI pieces (like kitchen cabinets)
  • services/ = where you keep shared logic (like utilities drawer)
  • models/ = where you keep data types (like filing cabinet)

Why organize?

  • ✅ Easy to find files
  • ✅ Team understands structure
  • ✅ No confusion or mix-up
  • ✅ Professional code
  • ✅ Scales as project grows

🏠 The Main Folders (What Goes Where)

Complete Angular App Structure

my-app/ ├── 📦 src/ │ ├── 🎨 app/ │ │ ├── 🧩 components/ │ │ ├── 🔧 services/ │ │ ├── 📋 models/ │ │ ├── 🎯 pipes/ │ │ ├── 🔐 guards/ │ │ ├── 🌐 interceptors/ │ │ ├── app.component.ts │ │ ├── app.module.ts │ │ └── app-routing.module.ts │ ├── 🖼️ assets/ │ ├── ⚙️ environments/ │ ├── main.ts │ └── index.html ├── ⚙️ angular.json ├── 📄 package.json └── 🔵 tsconfig.json

💡 Don't worry about all the details!

You'll use mainly: components/, services/, and models/ for 80% of your work.

📂 Understanding Each Main Folder

🧩 components/

What goes here: All the UI pieces of your app

Examples: Button, Header, Sidebar, User Card, Form, List, Modal, Navigation

🔧 services/

What goes here: Shared code and logic

Examples: UserService, AuthService, ApiService, DataService

📋 models/

What goes here: Data type definitions

Examples: User.ts, Product.ts, Order.ts, interfaces

🎯 pipes/

What goes here: Data transformers

Examples: Date formatter, Currency formatter, Custom pipes

🔐 guards/

What goes here: Permission checkers

Examples: AuthGuard (only logged in), AdminGuard (only admin)

🌐 interceptors/

What goes here: Request middlewares

Examples: Add auth token, error handling, loading state

🖼️ assets/

What goes here: Static files

Examples: Images, icons, fonts, documents, videos

⚙️ environments/

What goes here: Settings for different environments

Examples: development.ts, production.ts with API URLs

🎯 Real Example: User Management App

Let's say you're building an app that shows users and lets you edit them. Here's what your folder structure looks like:

my-app/ └── src/ └── app/ ├── components/ │ ├── user-list/ │ │ ├── user-list.component.ts │ │ ├── user-list.component.html │ │ ├── user-list.component.css │ │ └── user-list.component.spec.ts │ │ │ ├── user-card/ │ │ ├── user-card.component.ts │ │ ├── user-card.component.html │ │ └── user-card.component.css │ │ │ └── user-form/ │ ├── user-form.component.ts │ ├── user-form.component.html │ └── user-form.component.css │ ├── services/ │ └── user.service.ts (fetches/saves user data) │ └── models/ └── user.model.ts (defines what a User looks like)

✅ This structure makes sense because:

  • All UI for users is in components/user-*
  • User data logic is in services/user.service.ts
  • User data structure is in models/user.model.ts

🚀 How to Build Your Own Structure

1

Create Angular Project

Run: ng new my-app

This creates all folders for you automatically!

2

Create Components for UI

Run: ng generate component components/header

This creates the header component in components/ folder

3

Create Services for Logic

Run: ng generate service services/user

This creates user service in services/ folder

4

Create Models for Data

Manually create: models/user.model.ts

Define what data looks like (User interface)

5

Connect Everything

Component → uses Service → gets data → uses Model

Follow the structure and everything works smoothly!

📄 Component Files (Inside components/)

When you create a component, it has 4 files. Let's understand each:

🧠 user-list.component.ts

The Logic of the component

  • Variables and data
  • Methods (functions)
  • Click handlers
  • Business logic

Think: The BRAIN

👁️ user-list.component.html

The Display of the component

  • What it looks like
  • Where buttons are
  • What text shows
  • Form inputs

Think: The VIEW

🎨 user-list.component.css

The Styling of the component

  • Colors
  • Fonts
  • Sizes
  • Spacing

Think: The APPEARANCE

🧪 user-list.component.spec.ts

The Tests for the component

  • Check if logic works
  • Check if display is correct
  • Test edge cases
  • Ensure nothing breaks

Think: The QUALITY CHECK

🧩

A Component = 4 Files Working Together

Brain (TS) + View (HTML) + Look (CSS) + Test (Spec)

✅ Best Practices (Do's & Don'ts)

✅ DO THIS

  • Keep components small
  • One component per file
  • Put services in services/
  • Put data types in models/
  • Group related files
  • Use clear file names
  • Create subfolders by feature

❌ DON'T DO THIS

  • Mix components and services
  • Put everything in one folder
  • Create too many nested folders
  • Put logic in component HTML
  • Use vague file names
  • Mix concerns (UI + logic + data)
  • Duplicate code instead of using services

🔄 How Folders Connect (Data Flow)

🖥️ Component (in components/)

Displays UI to user - calls a Service to get data

↓

Component asks: "Give me user data!"

🔧 Service (in services/)

Gets data from backend - returns it to Component

↓

Service fetches from database - returns formatted data

📊 Model (in models/)

Defines what the data looks like - type checking

↑ Back up the chain ↑

Service returns User[] based on User model

🖥️ Component Displays Data

Component loops through users and shows them

📊 The Connection:

Component 🔄 Service 🔄 Model

They work together to build your app!

❓ Common Questions

Q: Do I have to follow this structure?

A: Yes! This is the standard Angular way. It makes your code clean and scalable.

Q: What if my app is very small?

A: Still follow this structure! It's good practice. Even small apps grow eventually.

Q: Where do I put my CSS?

A: In component.css file next to the component. Each component has its own styles.

Q: What's the difference between components and services?

A: Components = Visual stuff (what user sees) | Services = Logic stuff (what happens behind the scenes)

Q: Can I create more folders?

A: Yes! Create subfolder for features (like users/, products/, etc inside components/)

Q: I'm confused about models/

A: Models just define the shape of data. Example: "A User has name, email, age properties"

📝 Quick Summary (Remember This!)

The 3 Most Important Folders:

🧩 components/

Where you put UI elements that user sees

Use for: Buttons, Forms, Cards, Pages

🔧 services/

Where you put logic and data fetching

Use for: API calls, Data logic, Authentication

📋 models/

Where you define what data looks like

Use for: Interfaces, Types, Data structures

The Basic Rule:

Component needs data? → Call Service → Service uses Model to get/send data → Component displays using Model type
